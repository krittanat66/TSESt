# property-benefit-memo

ช่วยร่าง ตรวจสอบ และจัดรูปแบบ **บันทึกข้อความ** ราชการสำหรับงานจัดประโยชน์ทรัพย์สิน (ที่ดิน/อาคาร/สัญญาเช่า) ให้ตรงตามแบบฟอร์มมาตรฐาน **ท.ก. ๖๒** และภาษาราชการที่หน่วยงานใช้จริง

ปัญหาหลักที่ skill นี้แก้: **ตัวสะกดผิด** และ **รูปแบบผิด** ในบันทึกข้อความ — เอกสารประเภทอื่น (สัญญา, แบบฟอร์ม) มักมี pattern ตายตัวอยู่แล้วจึงมีปัญหาน้อยกว่า

## กฎสำคัญที่สุด: ห้าม hardcode ข้อมูลอ่อนไหว

**ห้ามใส่ตัวเลขค่าเช่า/ค่าธรรมเนียม/ราคาประเมิน, ชื่อบุคคลจริง, หรือกรณีตัวอย่างจริงลงใน skill นี้หรือในโค้ด** ทุกครั้งที่ร่างหรือแก้เอกสาร ให้ใช้ **placeholder** (เช่น `[อัตราค่าเช่า]`, `[ชื่อผู้เช่า]`, `[เลขที่สัญญา]`) แล้วให้ผู้ใช้กรอกตัวเลข/ชื่อจริงเอง ตัวเลขและเกณฑ์ที่แท้จริงอยู่ในระเบียบภายในของสำนักงานซึ่งเป็นความลับ — ห้ามเดาหรือจำจากเอกสารที่เคยเห็น

## ขั้นตอนการทำงาน

1. **ระบุประเภทธุรกรรม** — ถามผู้ใช้หรือดูจากบริบทว่าเป็นธุรกรรมประเภทไหนใน 21 ประเภท (`references/transaction-types.md`) เพราะกำหนด:
   - ต้องใช้ one-stop service (เสร็จวันเดียว) หรือ flow อนุมัติหลายชั้น
   - เอกสารประกอบที่ต้องแนบ (ดูคอลัมน์ "เอกสารประกอบ" ในไฟล์อ้างอิง)
2. **เลือกโหมด**:
   - **ร่างใหม่** → ใช้โครงสร้าง 3 ย่อหน้าด้านล่าง เติม placeholder ตามข้อมูลที่ผู้ใช้ให้มา
   - **ตรวจ/แก้ไข** → ใช้ checklist ด้านล่างไล่ตรวจทุกข้อ แล้วรายงานเฉพาะจุดที่ผิด พร้อมข้อเสนอแก้
   - **จัดรูปแบบ** → จัดให้ตรงผังฟอร์มด้านล่างโดยไม่เปลี่ยนเนื้อหา
3. **ตรวจสอบคำศัพท์เฉพาะ** ที่ใช้ในบันทึกให้ตรงกับ `references/glossary.md` (เช่น อย่าสับสน "สัญญาเช่าประเภทที่ 1" กับ "ประเภทที่ 2")
4. **ก่อนส่งงานให้ผู้ใช้** ไล่ checklist ท้าย SKILL.md อีกครั้งเสมอ

## โครงสร้างฟอร์ม ท.ก. ๖๒ (บันทึกข้อความ)

```
                                                    [รหัสแบบฟอร์ม: ท.ก. ๖๒]
                        บันทึกข้อความ
                สำนักงานทรัพย์สินพระมหากษัตริย์

ที่ [เลขที่หนังสือ]                          วันที่ [วัน เดือน พ.ศ.]

เรื่อง  [หัวเรื่องสั้น กระชับ ขึ้นต้นด้วย "ขอ..." หรือระบุเรื่องตรง ๆ]

เรียน  [ตำแหน่งผู้รับ เช่น ผู้อำนวยการทรัพย์สินพระมหากษัตริย์ — ห้ามใช้ชื่อบุคคล]

     ด้วย [ที่มา/ความเป็นมา — ใครเกี่ยวข้อง เกิดอะไรขึ้น ทำไมต้องเสนอเรื่องนี้]

     ในการนี้ [หน่วยงานเจ้าของเรื่อง] ได้พิจารณาแล้วเห็นสมควร [การวิเคราะห์/
     ข้อเสนอที่เป็นรูปธรรม อาจแทรกตารางข้อมูลประกอบได้]

     จึงเรียนมาเพื่อพิจารณาอนุมัติ [สรุปสิ่งที่ขออนุมัติ + วันที่มีผลบังคับใช้ถ้ามี]

                                    ลงชื่อ ....................................
                                          (ชื่อ-นามสกุลผู้เสนอเรื่อง)
                                          [ตำแหน่ง]
                                          [วันที่]

──────────────────────── ส่วนอนุมัติ (ท้ายบันทึก) ────────────────────────
        อนุมัติ / ไม่อนุมัติ / มีความเห็นดังนี้ ...

  [บล็อกผู้ลงนามที่ 1]          [บล็อกผู้ลงนามที่ 2]        [บล็อกผู้ลงนามที่ 3]
  ลงชื่อ ..................       ลงชื่อ ..................     ลงชื่อ ..................
  (ชื่อ-นามสกุล)                 (ชื่อ-นามสกุล)               (ชื่อ-นามสกุล)
  ตำแหน่ง                        ตำแหน่ง                      ตำแหน่ง
  วันที่                          วันที่                        วันที่
```

**ข้อสังเกตสำคัญของฟอร์มนี้:**
- ใช้สูตร 3 ท่อนเสมอ: **"ด้วย..." → "ในการนี้..." → "จึงเรียนมาเพื่อ..."** ห้ามข้ามท่อนใดท่อนหนึ่ง
- ส่วนอนุมัติรองรับ **ผู้ลงนามหลายคนพร้อมกัน** (multi-signatory ไม่ใช่ลำดับเดียว) — ธุรกรรมมูลค่าสูงมักต้องอนุมัติร่วมจากรองผู้อำนวยการหลายสายงานก่อนถึงผู้อำนวยการ
- "เรียน" ใช้ตำแหน่งเสมอ ไม่ใช้ชื่อบุคคล
- ตารางแทรกในย่อหน้า "ในการนี้" เป็นที่ยอมรับ (เช่น ตารางเปรียบเทียบอัตรา)

## Checklist ตรวจสอบก่อนส่ง

**ตัวสะกด/ภาษา:**
- [ ] ไม่มีตัวสะกดผิด (โดยเฉพาะคำศัพท์เฉพาะทาง — เทียบกับ `references/glossary.md`)
- [ ] ใช้เลขไทยหรือเลขอารบิกสม่ำเสมอตลอดเอกสาร (ไม่ปนกัน)
- [ ] วันที่เป็น พ.ศ. และเดือนสะกดเต็ม (ไม่ย่อ)
- [ ] ไม่ใช้ภาษาพูด/คำทับศัพท์ที่ไม่เป็นทางการ

**โครงสร้าง:**
- [ ] มีครบ 3 ย่อหน้า (ด้วย/ในการนี้/จึงเรียนมาเพื่อ) ตามลำดับ
- [ ] "เรื่อง" กระชับ สื่อสาระสำคัญ ไม่ยาวเกิน 1 บรรทัด
- [ ] "เรียน" ใช้ตำแหน่ง ไม่ใช้ชื่อบุคคล
- [ ] เลขที่และวันที่อยู่ในตำแหน่งถูกต้อง (มุมบน)

**เนื้อหา:**
- [ ] ระบุประเภทธุรกรรมชัดเจน (ตรงกับ 1 ใน 21 ประเภทใน `references/transaction-types.md`)
- [ ] ไม่มีตัวเลข/ชื่อจริงที่ควรเป็น placeholder หลงเหลืออยู่ (ตรวจหา `[...]` ที่ยังไม่กรอก)
- [ ] ถ้าธุรกรรมต้องมีเอกสารประกอบ ระบุไว้ในบันทึกว่าแนบอะไรบ้าง

**ลายเซ็น:**
- [ ] บล็อกลงนามครบ: ชื่อ-สกุล / ตำแหน่ง / วันที่ ทุกบล็อก
- [ ] จำนวนบล็อกผู้อนุมัติตรงกับระดับธุรกรรม (ดูคอลัมน์ผู้มีอำนาจใน transaction-types.md)
